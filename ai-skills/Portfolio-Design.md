# Portfolio design

Keywords: portfolio, personal website, software engineer, developer

- Treat a portfolio as a designed page, not a list of facts. Establish hierarchy through typography, spacing, alignment, and a restrained palette.
- Start with the person's real name and role. Add a short introduction only when the user supplied enough information; never invent jobs, clients, awards, skills, or contact details.
- Give the first viewport a clear visual idea. For an all-black request, use near-black surfaces, off-white text, subtle gray separators, and one restrained accent. Avoid pure-white cards and generic gradients.
- Build a compact navigation, an intentional hero, a projects section, and a closing contact/footer section. Navigation anchors must reach real sections.
- Make supplied project URLs visible, clickable, and associated with the correct project. If no description is known, use a neutral label such as “View project”; do not guess what the project does.
- Use a responsive grid that becomes one column on narrow screens. Check long URLs, headings, and navigation for overflow.
- Prefer purposeful motion: subtle entrance or hover feedback, short durations, and `prefers-reduced-motion` support. Motion must not hide content when JavaScript fails.
- Use real content and complete CSS. A page with default browser fonts and blue links is unfinished.
